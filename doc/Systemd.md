# Systemd integration

teslausb-ng installs a hardened systemd unit at `/lib/systemd/system/teslausb.service`.
The unit is generated by `setup/pi/configure.sh` during initial setup and
is enabled automatically on first boot.

## What runs as a service

The single `teslausb.service` runs `/root/bin/archiveloop`, which in turn
spawns child loops for snapshotting, free-space management, log rotation,
and the Wi-Fi watchdog. All four background loops live inside one
process tree so a single `systemctl restart teslausb` cycles everything.

## Hardening (vs upstream)

| Setting                  | Upstream     | teslausb-ng           | Why                                                  |
|--------------------------|--------------|-----------------------|------------------------------------------------------|
| `Restart`                | `always`     | `always`              | Archive loop should run whenever the system is up    |
| `RestartSec`             | (default 0)  | `5s`                  | Avoid hot-looping during transient mount failures    |
| `StartLimitIntervalSec`  | (default 10) | `600`                 | Long enough window to catch real crash loops         |
| `StartLimitBurst`        | (default 5)  | `20`                  | Tolerate the periodic short cycles archiveloop does  |
| `StandardOutput`/`Error` | (default)    | `journal`             | `journalctl -u teslausb` becomes the source of truth |
| `SyslogIdentifier`       | —            | `teslausb`            | `journalctl -t teslausb` aggregates all log entries  |
| `TimeoutStopSec`         | (default 90) | `30s`                 | Tesla disconnects fast; we don't need a long stop    |
| `MemoryAccounting`       | —            | `true`                | `systemctl status` shows memory usage                |

These settings resolve the bug where teslausb stopped mounting after a few
weeks of operation (issue [#654](https://github.com/marcone/teslausb/issues/654))
in cases where the cause was an unsupervised crash inside the bash daemon.

## Operating

```bash
# View live logs from the archive loop
journalctl -u teslausb -f

# Show only warnings and errors
journalctl -u teslausb -p warning..err

# Restart after editing /root/teslausb_setup_variables.conf
systemctl restart teslausb

# Disable archiving temporarily without uninstalling
systemctl stop teslausb
```

## Structured logging

`run/_log.sh` adds journald-aware `log_info` / `log_warn` / `log_error`
helpers that newer scripts use. They write to both the on-disk
`/mutable/archiveloop.log` (for users who SSH in to grep) and to journald
with a proper priority (for `journalctl -p`).

The existing `log()` function inside `run/archiveloop` remains in place
during the transition. New code should prefer the `_log.sh` helpers; old
code is migrated as it's touched.
